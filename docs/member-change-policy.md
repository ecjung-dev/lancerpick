# 닉네임 변경 주기·비밀번호 권고 기준일(U6/B3)

2026-11-09, 황준범. `feature/member-change-policy`, main `44c7857` 기준 로컬 구현. 주문 표시 보완 PR #144와 별도다. 알림 발송·배치·반복 회차·직접 이동 연결은 정은찬 후속이며, 이번 작업으로 U6 전체가 완료된 것은 아니다.

## 확정 정책

- 닉네임 첫 변경은 즉시 가능하다. 변경 후 한국 시간의 달력 6개월이 지나면 다시 변경할 수 있다. 월말은 도착 월의 마지막 날로 맞춘다. 180일 고정 계산이 아니다.
- 공백 정리 후 같은 이름이면 성공하되 변경일·일반 updated_at을 갱신하지 않는다. 유효성 오류·기간 제한·트랜잭션 실패도 변경일을 갱신하지 않는다.
- 비밀번호는 변경 강제가 아닌 권고다. 언제든 기존 형식·현재 비밀번호 검사에 따라 변경할 수 있으며 기존 세션 폐기 정책을 유지한다.
- **사용자 확정(2026-11-09): 기존 회원의 첫 권고 기준은 기능 도입 시각이다.** 가입일/일반 updated_at으로 과거 비밀번호 변경일을 추정하지 않는다. 개인 DB마다 V11 적용 시각이 해당 DB의 도입 시각이다.
- 신규 가입·성공한 변경·성공한 재설정은 실제 시각과 권고 기준일을 함께 기록한다. 같은 비밀번호 변경 거절·실패·재설정 토큰 재사용은 기준을 갱신하지 않는다. 닉네임 변경·세션 무효화도 비밀번호 기준을 바꾸지 않는다.

## V11 데이터와 호환

기존 마이그레이션은 수정하지 않고 `V11__add_member_change_policy_dates.sql`로 members에 세 컬럼을 추가한다. 테이블 추가는 없다.

| 컬럼 | 기존 회원 | 신규 가입 / 후속 갱신 |
| --- | --- | --- |
| display_name_changed_at | NULL: 첫 변경 허용 | 실제 닉네임 변경 성공 시각 |
| password_changed_at | NULL: 과거 시각 알 수 없음 | 가입·비밀번호 변경/재설정 성공 시각 |
| password_recommendation_base_at | V11 도입 UTC 시각 | 가입·비밀번호 변경/재설정 성공 시각 |

모두 UTC DATETIME(6)이며 `LOCAL_DATE_TIME` 매핑을 사용한다. 권고 기준 컬럼은 NOT NULL, 기존 개발/테스트 SQL이 컬럼을 생략해도 호환되도록 `DEFAULT (UTC_TIMESTAMP(6))`를 둔다. 신규 JPA 가입은 같은 가입 시각을 명시적으로 저장한다. 도입 시각은 과거 실제 변경일과 구분하며, 권고 알림을 이미 보냈다는 뜻이 아니다.

## 회원 API와 화면

기존 Member 응답(가입·로그인·GET/PATCH `/api/me`)에 `displayNameChangeAvailableAt`만 추가한다. 첫 변경은 null, 이후는 한국 달력 6개월을 계산한 UTC 오프셋 문자열이다. 과거 시각이라면 다시 변경 가능하다. 비밀번호 변경 시각·권고 기준·원문/해시는 이 응답에 추가하지 않는다.

PATCH `/api/me`는 기존 회원 배타 잠금 아래 현재 시각과 기간을 검사한다. 아직 변경할 수 없으면 409 `DISPLAY_NAME_CHANGE_NOT_ALLOWED`이며 다시 GET하면 다음 날짜를 확인할 수 있다. 다른 이름의 동시 요청은 한 건만 성공한다. 표시 이름이 같은 재요청은 기간을 소비하지 않는다.

내 정보 화면은 다음 가능일을 한국 시간으로 보여 주고 제한 중 닉네임 입력·저장만 막는다. 비밀번호 폼은 계속 사용할 수 있다. 열린 화면에서도 기한 도달 시 버튼을 다시 활성화한다. 클라이언트 시계는 안내용이고 실제 요청은 서버가 최종 검사한다. 409를 받으면 본인 정보를 재조회한다.

## 정은찬·김창재 연결 계약

`PasswordRecommendationQuery.find(long memberId)`는 잠금 없이 `Optional<Basis>`를 반환한다. 존재하지 않는 회원은 empty, 양수가 아닌 ID는 내부 호출 오류다. JPA 스칼라 projection만 조회하며 인증정보·이메일은 읽지 않는다.

| Basis | 의미 |
| --- | --- |
| memberId | 대상 회원 |
| passwordChangedAt | 실제 마지막 기록 시각. 기존 회원은 null 가능 |
| basisAt | 중복 원천에 사용할 권고 기준 시각. null 아님 |
| firstRecommendedAt | basisAt의 한국 달력 6개월 후, UTC |

정은찬은 이 기준을 읽어 `PASSWORD_CHANGE_RECOMMENDED` 발송·회차/중복 원천·스케줄링을 연결한다. 기준일 이후 비밀번호가 바뀌면 예전 기준으로 알림이 생성되지 않도록 알림 저장 트랜잭션의 최신 기준 재확인/회원 잠금 여부를 함께 정해야 한다. 이 조회 서비스가 재확인·알림 저장을 원자적으로 묶어 주지는 않는다. 기존 아웃박스의 MEMBER 집계·order_id NULL 계약을 유지한다. 미변경 회원에게 반복하는 회차 계산과 실제 스캔 쿼리·인덱스는 발송 구현 시 별도 확정한다.

김창재의 기존 변경/재설정 경로는 `Member.changePassword`를 재사용하므로 기록을 한곳에서 갱신한다. 세션·요청 제한·메일·토큰 소비와 기존 롤백 경계를 바꾸지 않았다. 기존 회원 초기 기준에 관한 미정 문구보다 위 사용자 결정을 우선한다.

## 로컬 검증

V10까지 적용한 격리 MySQL 8.4에 과거 회원을 넣은 뒤 V11로 업그레이드해 실제 변경일 NULL·도입 기준일·기존 생성/갱신 시각·비밀번호 해시 보존을 확인했다. DB 세션을 +09:00으로 바꿔도 생략 INSERT 기본값이 UTC인 것을 확인했고 Flyway 11개 validate를 통과했다.

관련 백엔드 51건과 프런트 typecheck·lint·276건·build가 통과했다. 전체 백엔드 검사와 추가 HTTP 계약 검사는 후속 검증 중이며, 이 중간 결과를 최종 전체 검사로 표시하지 않는다. 기존 번들 크기/deprecated API 경고는 유지한다. 개인 DB에 V11을 적용하지 않았고 push·PR·main 병합·실제 권고 발송은 별도다.
