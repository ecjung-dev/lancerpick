# 황준범 담당 진행 현황

기준일: 2026-11-02. 대상: 지갑·마이페이지 연결·토스 테스트 충전·주문 적립금 결제·환불·판매 수익 정산. 프로젝트 전체 팀 진행률이 아니다.

## 1. 진행률 추정

**현재 약 50%.** 실제 작업 시간이나 테스트 개수로 산출한 확정 수치가 아니라, 아래 기능별 예상 작업량 가중치로 계산한 계획용 추정이다. 팀원이 연결한 코드와 종단 간 검증 결과에 따라 갱신한다. 신청/조회 준비 시점은 약 40%였고, 서버 승인·지급·본인 재확인 및 대역/DB 검증을 10%p 추가 반영했다. 실제 토스 키 연동·화면·자동 복구가 남아 있어 토스 항목을 전부 완료 처리하지 않는다.

## 2. 남은 작업 순서

1. 회원 연동 확인: 가입에서 지갑 초기화 호출, AuthenticatedMember 구현, 실제 로그인 후 마이페이지 연결, 로그아웃/계정 전환 캐시 정리. 인증 담당자와 공동 검증한다.
2. 토스 실제 연동: 구현한 승인 클라이언트·API를 테스트키·실제 결제창으로 검증한다. 현재는 대역/DB 검증까지 완료.
3. 충전 복구 운영: 본인 재확인은 구현했으며 자동 재확인·운영자 처리 범위·웹훅 필요 여부를 결정하고 검증한다.
4. 충전 화면: 금액 선택, 토스 SDK, 성공/실패 경로, 서버 승인 요청·결과 조회, 401/금액 오류/결과 불명확 표시.
5. 상품 주문 결제: 주문 담당자와 호출·상태·이력 경계 합의, 주문→지갑 잠금, 차감·결제·원장·진행 상태를 같은 트랜잭션으로 처리.
6. 취소·환불: 주문 취소와 적립금 복구 원자성, 반복 환불·결제/취소·구매 확정 충돌 검증. 토스 충전 취소와 구분한다.
7. 구매 확정·정산: 완료 상태와 정산 기록 동시 확정, 수수료 10% 원 미만 버림, 중복 정산 차단, 판매 수익 조회/화면.
8. 실제 인증·화면·DB·테스트키 기반 전체 시나리오와 배포 검증, 팀원 재현·문서·발표 근거 정리.

## 3. 이번 단계 결과

`feature/wallet-topup-api`에서 POST /api/me/wallet/topups와 GET /api/me/wallet/topups/{id}를 구현했다. 신청 저장은 지급이 아니며 지갑 잔액·원장을 변경하지 않는다. 새 DB/Flyway 변경은 없다. 상세 계약은 [충전 API](wallet-topup-api.md)를 따른다.

격리 MySQL 8.4에서 V1/V2·기본 validate와 전체 clean build --offline을 통과했다. 전체 118건 중 새 API 검사는 16건이다. 새 검사는 실제 Security 필터·Controller·Service·DB를 사용하되 로그인은 테스트 principal로 대체한다. 토스 통신·실제 로그인·브라우저 연동 검증은 아니다. 전용 컨테이너·볼륨은 정리했다. 이번 API 변경은 아직 커밋·push하지 않았다.

후속: [승인·지급·본인 재확인](wallet-topup-approval.md)을 추가했다. 전체 빌드 148건을 통과했으며 실제 제공자 대신 대역을 사용한다. 테스트키를 사용한 실제 결제창 확인과 프런트 연결은 남아 있다.
