# 랜서픽 구현 준비 작업표

역할 배정 갱신 2026-10-29: [확정 담당·지원 원칙·업무 비중](work-plan.md#확정-역할-배정)을 따른다. 상세 일정·검토자·배포 담당은 별도 확정한다.

작성일: 2026-10-29. 아래 역할 배정은 사용자가 확정한 내용이다. 구현 순서·C/D 호출 경계는 검토 제안이며, 상세 일정·검토자·배포 담당은 미확정이다.

## 확정 역할 배정

| 역할 | 담당자 | 핵심 책임 | 초기 예상 업무 비중 |
| --- | --- | --- | --- |
| C · 조장 | 정은찬 | 주문 상태·납품·수정·취소·구매 확정·통합 조율 | 32% |
| D · React 공통 | 황준범 | 적립금·결제·환불·정산·공통 프런트 기반·API 연결 방식 | 34% |
| A | 김창재 | 회원가입·로그인·권한·관리자 상품 조회·숨김·복구 | 17% |
| B | 박소현 | 판매자 프로필·상품·검색·후기 | 17% |
| 합계 | 4명 | MVP 구현과 공통 지원 | 100% |

각자 자기 기능의 화면·API·DB·테스트·문서를 끝까지 책임진다. 정은찬·황준범은 어려운 설계·로직과 공통 기반을 지원한다. 김창재·박소현의 기능 전체를 대신 구현한다는 의미는 아니다. 기능별 반복 화면·조회는 해당 담당자가 구현한다.

비중의 분모는 기능 구현·화면·DB·테스트·리뷰·통합·조율을 포함한 전체 예상 업무량이다. 32·34·17·17%는 실제 시간 측정이나 세부 작업 견적 없이 산정한 초기 추정이며 기여도·평가점수·확정 노동시간이 아니다. 두 핵심 지원 담당 합계 66%, 나머지 담당 합계 34%를 출발점으로 두고 첫 통합 후 실제 부담을 확인해 조정한다.

기본 교차 검토 연결은 A↔B, C↔D라는 기존 출발안을 유지한다. 실제 PR 검토자는 작업별 지정하며, 배포 담당과 React 공동 개발 담당은 별도 지정한다. 미확정 담당을 임의로 실명 배정하지 않는다.

## 2. C·D 호출 경계 제안

현재 확정 원칙은 업무 시작 서비스의 단일 트랜잭션과 주문 → 구매자 지갑 잠금 순서다. 아래는 이를 구체화하는 제안이며 클래스 이름이나 구현 완료를 뜻하지 않는다.

| 업무 | 시작점 제안 | 같은 트랜잭션 안의 책임 |
| --- | --- | --- |
| 최초 결제 | 주문 결제 조정 서비스(C·D 공동 검토) | 주문 잠금·자격 검증 → D의 지갑·결제 처리 → C의 진행 상태·납기·확인 시각·이력 |
| 유료 취소·승인 | 주문 취소 서비스(C) | 주문 잠금·당사자·취소 자격 검증 → D의 환불 → C의 주문 취소·대기 요청 종료·이력 |
| 구매 확정 | 주문 완료 서비스(C) | 주문 잠금·검수 대기·취소 요청 검사 → D의 정산 생성 → C의 완료·이력 |

D의 내부 금액 처리는 같은 트랜잭션에 참여한다. C→D 호출 중 D가 다시 C의 업무 시작 서비스를 호출하는 순환을 만들지 않는 방향으로 검토한다. 금액 처리 실패를 숨기지 않고 전체를 롤백한다. 잠금 담당 서비스, 내부 메서드 입력·반환값, 재호출 결과까지 합의한 뒤 구현한다.

역할 기호는 위 확정 담당에 대응한다. 목표일·PR·테스트 결과는 실제 진행 시 추가한다. 순서는 제안이며 최초 배포는 작은 인증·DB 흐름이 연결되면 기능 개발과 병행한다. 공식 일정은 MVP 명세의 목표를 따르고 실제 진척에 따라 조정한다.
