## 화면 상태

- `/`: 현재 로컬은 `/api/demo/products`·`/api/demo/categories` 예시 조회다. PR #36은 `/api/products`·`/api/categories` 실조회로 전환하며 DB를 사용하는 기본 백엔드가 필요하다. demo 실행으로 실제 검색을 대신하지 않는다.
- `/login`, `/signup`: 안내 화면이며 로그인·가입 폼 완성이 아니다.
- `/orders`, `/orders/:id`: 목록·상세 및 수락·거절·결제·직접 취소·구매 확정 화면. 납품·수정·취소 요청 입력 화면은 별도다.
- `/mypage`, `/mypage/wallet`: 현재 로컬은 `GET /api/me` 확인 후 본인 잔액·내역 조회. 인증 실패를 예시 잔액으로 대체하지 않는다.
- `/mypage/settlements`: 판매 수익 조회. `/mypage/wallet/topup`과 그 하위 결과 경로는 테스트 충전 화면이다.
- `/mypage/wallet/preview`, `/mypage/wallet/topup/preview`: 명시적인 예시 화면이며 실제 지급 근거가 아니다.

## 다음 작업

1. 인증 담당자와 로그인·가입 폼 및 전역 인증 상태를 연결한다. 로그인·로그아웃·계정 변경 시 `clearCsrfToken()`·`clearWalletCache()`를 연결한다.
2. 인증 담당자에게 `AuthService.login()`의 판매자 프로필 조회가 세션 저장 뒤에 있다는 기존 검토 항목을 확인한다. 해당 조회 실패 시 응답과 세션 상태의 일관성은 아직 해결 완료로 표시하지 않는다.
3. 사용자 실행으로 토스 테스트 충전 5만원과 잔액·내역 반영을 확인했다. [충전 화면 후속 기록](wallet-topup-frontend.md)에 따라 초기 약관/버튼 수정과 중복 지급·실패·모바일 경로를 추가 확인한다. 키는 개인 설정으로만 관리한다.
4. 납품·수정·취소 요청 화면 및 상품/주문 작성 화면을 연결하고, 구매자·판매자의 브라우저 거래를 확인한다.
5. 관련 PR 병합 후 최신 main과 로컬 추가 작업을 합쳐 전체 회귀를 실행한다. 배포·발표용 증거와 남은 제한을 정리한다.

전체 작업률은 화면·실제 제공자·배포 미검증을 포함한 새 견적 없이 단정하지 않는다. 과거 40%·50% 표기는 당시 황준범 담당 범위의 추정치다.
