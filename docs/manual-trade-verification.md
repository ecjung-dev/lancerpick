# 사용자 수동 거래 검증 현황

정리일 2026-11-04. 문서 대조 기준은 로컬 소스 `235ae8f`다. 아래 결과는 사용자가 이 대화에서 직접 확인했다고 전달한 내용이며, 문서 작성 중 새로 테스트를 실행한 결과와 구분한다. 사용자가 실행한 환경의 정확한 커밋·브라우저·세부 DB 수치·화면 캡처는 별도 제출되지 않았다.

## 확인 완료

| 흐름 | 사용자 확인 결과 |
| --- | --- |
| 상품 등록 → 주문 → 판매자 수락 → 결제 → 납품 → 구매 확정 → 정산 | 실제 화면에서 기능이 정상 동작한다고 확인 |
| 주문 취소·환불·잔액 반환 | 실제 화면에서 정상 동작 확인 |
| 토스 테스트 충전 | 충전 성공·지갑 잔액·내역 표시 확인 |
| 초기 약관 상태·체크 해제/재체크 | 결제 버튼 상태 확인 |
| 충전 금액 변경 | 금액 재선택·결제 금액 일치 확인 |
| 결제창 취소·세션 만료·완료 화면 새로고침·결과 재확인 | 사용자가 앞서 확인한 항목임을 재확인. 기본 충전 실패 흐름의 잔여 작업에서 제외 |
| 관리자 상품 숨김·복구(실제 데이터, 김창재) | 시연 SQL 상품으로 관리자 목록 표시, 숨기기 후 숨김 배지·판매 중 유지·버전 증가·운영 이력·공개 목록 제외, 복구 후 이력 2건·공개 목록 재표시 확인. [상세](admin-product-moderation.md#관리자-화면-2026-11-04-featureadmin-product-ui) |
| 로그아웃 후 다른 계정 로그인 | `test2` 접속 → 로그아웃 → `test3` 접속 후 이전 계정 정보가 남지 않는 것을 사용자 확인 |

한 계정으로 구매·판매를 겸한다. 별도 구매자·판매자 계정 유형은 없으며, 본인 상품 주문이 금지되므로 서로 다른 두 회원이 해당 거래에서 구매자·판매자 역할을 맡는다.

위 수동 확인은 자동 테스트 수에 더하지 않는다. 자동 검사의 동시 요청·원장 1회 생성·실패 롤백 결과와 사용자의 실제 화면 확인을 구분한다. 강제 네트워크 단절·정확한 timeout 경과·모든 UNKNOWN 제공자 응답 조합을 수동으로 재현했다고 확대하지 않는다.

## 남은 연결 확인

사용자 지정에 따라 아래 상품 변경·숨김과 기존 거래 유지, 모바일 조작 확인은 다른 담당자가 진행한다. 황준범의 개인 잔여 작업에서는 제외한다. 구체적인 수행자·완료 결과는 해당 담당자가 확인 후 기록한다.

- 주문 후 원상품 수정·판매 중지·관리자 숨김을 적용해도 기존 주문 조건·납품·취소/환불 처리가 유지되는지 교차 기능 확인.
- 관리자 상품 상세·숨김/복구 화면의 실제 데이터 기반 동작은 2026-11-04 김창재가 확인했다(위 표). 숨김 상품 공개 상세 직접 접근·판매 재개와 숨김의 관계·동시 처리 화면 확인은 남아 있다.
- 모바일 브라우저의 화면 조작 확인. 기능별 자동 렌더링 검사와 구분.

이미 확인한 일반 거래·취소/환불·기본 충전 실패 흐름은 기본 잔여 작업에 다시 넣지 않는다. 관련 코드 변경이나 결함 발견으로 재검증이 필요해지면 대상과 이유를 명시한다.

## 보류 및 담당 경계

디자인 개선과 배포 작업은 사용자의 결정으로 보류한다. 상품 목록 관리·후기·표시 이름 변경 등 다른 담당자의 남은 개발은 [현재 현황](current-status.md)과 [작업표](work-plan.md)를 따른다. 토스 충전 취소·원결제수단 환불·출금은 별도 확장 범위다.

개발용 계정·상품이 필요하면 [수동 테스트 데이터 SQL](sql/seed-manual-trade-demo.sql)을 개인 개발 DB에서 실행한다. 같은 테스트 이메일이 있으면 생성을 거절하고 기존 데이터를 보존한다. 기존 계정의 비밀번호가 이 SQL의 공개 테스트 비밀번호라고 보장하지 않으므로 이전 생성 경로를 확인한다.
