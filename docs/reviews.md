# 후기 작성·조회

## 후기 요약·별점 필터 (S3)

- 공개 후기 조회에 선택 쿼리 `rating=1`~`rating=5`를 추가한다. 생략 시 전체를 조회하고 범위 밖 또는 잘못된 값은 400 `VALIDATION_FAILED`로 응답한다.
- 응답의 `summary.averageRating`과 `summary.reviewCount`는 필터와 무관한 전체 상품 후기 기준이다. 후기 0건이면 평균은 `null`이다. `totalElements`와 `totalPages`는 선택한 필터 기준이다.
- 집계와 목록은 동일한 공개 상품과 후기 범위를 읽는다. 기존 최신순·공개 응답 필드·작성 정책을 유지한다. 상품 상세는 평균을 소수 첫째 자리까지 표시하고 필터를 바꾸면 첫 페이지로 이동한다.
- #105를 반영한 `main`(`9f9aa8f`) 기준 격리 MySQL 8.0의 후기 통합·공개 API 테스트와 프런트 자동 테스트 201건·빌드·린트를 통과했다. 실제 브라우저 조작과 원격 CI는 별도다.

2026-11-05 후속: 실제 거래 API로 완료한 주문의 후기 응답 유실 복구·좁은 화면 조작은 [브라우저 확인](product-review-browser-check.md)에 별도 기록한다. 기존 검사 수·구매 확정 fixture 검증과 구분하며 실기기 모바일 완료를 뜻하지 않는다.

2026-11-04, 박소현. `codex/reviews`에서 구현·검증. MVP·API·DB 설계·공통 백엔드/프런트 가이드에 따라 기존 reviews 테이블을 사용한다. 최초 기능 검증은 커밋 전 수행했고, 최신 main 통합 및 커밋·Push 검토 기록은 아래 후속 절을 따른다.

## 구현과 정책

- `POST /api/orders/{id}/review`: 세션 회원의 구매 확정(COMPLETED) 주문에 한 번만 작성, 성공 201. 별점은 JSON 정수 1~5, 글은 생략/null 가능. 문자열 숫자·소수·불리언·추가 필드는 400. 글은 공통 Unicode 가장자리 공백 제거·개행 정규화 후 1~2000 코드 포인트, 입력한 공백 글은 400이다.
- 기존 주문 명령과 동일하게 회원 공유 잠금 → 참여 주문 배타 잠금 순서로 처리한다. READ_COMMITTED에서 주문 잠금 후 후기 존재 여부를 검사하여 동시 요청을 직렬화하며 DB의 기존 주문 UNIQUE도 유지한다. 중복은 409 REVIEW_ALREADY_EXISTS, 미완료는 409 ORDER_STATE_CONFLICT, 판매자는 403, 타인/없는 주문은 404다. 세션·CSRF 설정 변경 없음.
- 후기 작성으로 주문 상태·이력·지갑·정산을 변경하지 않는다. 상품의 현재 숨김/판매 상태와 관계없이 기존 완료 주문의 구매자는 작성할 수 있다. 수정·삭제·판매자 답글은 MVP 범위 밖이다.
- `GET /api/products/{id}/reviews`: 공개·판매 중 상품만 비로그인 조회, 나머지는 404. page 기본0, size 기본20/허용1~100. 작성 시각·ID 내림차순, 범위 밖은 전체 건수와 빈 목록. 한 REPEATABLE_READ 읽기 트랜잭션에서 공개 여부·개수·목록을 읽는다.
- 공개 응답은 id,authorDisplayName,rating,content,createdAt만 반환한다. 주문·작성자 ID와 이메일을 노출하지 않는다. 작성 응답과 참여자 주문 상세에는 기존 계약대로 orderId가 있다. ID는 문자열, 저장 시각 UTC·응답 ISO UTC·화면 KST. 작성자명은 현재 회원 표시 이름을 사용한다.
- QueryDSL 조인/필요 열 조회, JPA 저장. 기존 V1/V2·의존성·공개 상품 DTO 변경 없음.

## 화면

- 주문 상세: WRITE_REVIEW 허용 행동이 있는 구매자에게 별점·선택 글 입력 폼 표시. 글 공백만 입력하면 선택 글을 null로 전송한다. 등록 중 중복 클릭 차단, 자동 POST 재전송 없음. 성공/오류 후 주문 상세와 공개 후기 쿼리를 재조회한다. 실패/불명확 결과에서는 입력을 잠그고 명시적인 주문 상태 재확인 후에만 다시 작성하도록 한다.
- 등록 후 기존 주문 상세의 구매 후기 기록을 표시하며 폼을 제거한다. 상품 상세에 공개 후기·작성자·별점·작성 시각·페이지 버튼을 표시한다. 목록의 page는 URL에 보존하며 로딩·실패·빈 목록·범위 초과를 구분한다. React 텍스트 출력으로 사용자 글을 HTML로 실행하지 않는다.

## 검증

- 격리 MySQL 8.0.46/lancerpick_ci에서 백엔드 전체 build 627건 통과, 실패·오류·건너뜀0. 신규6건: 정상 작성/중복/후기 포함 주문 상세, 권한/CSRF/상태, 엄격 JSON/Unicode2000자 경계, 공개 페이지/노출 제한, 숨김·판매 중지, 3개 동시 요청에서 1개 생성·2개 중복 응답.
- 최초 DB 기동 실패로 통합 검사가 연결 오류를 냈고, 전용 인스턴스의 기동 확인 후 재실행했다. 입력 테스트에서 소수 별점이 정수로 강제 변환되는 문제를 찾아 DTO 원본 JSON 타입 검증으로 수정한 뒤 전체 검사를 통과했다.
- 프런트 전체128건·build(타입 검사 포함)·lint 통과. 신규6건은 쿠키/CSRF/문자열 BIGINT/취소 signal, 입력 경계/정규화, 실패 POST 무재전송, 목록 렌더링·HTML 이스케이프·빈 목록/페이지 복구와 폼 안내를 검증한다.
- 실제 브라우저: 격리 회원 로그인 → 구매 확정 주문 상세 → 줄바꿈·emoji 포함 5점 후기 등록 → 폼 제거·저장된 후기 표시 → 상품 상세에서 동일 후기 → 로그아웃 → 상품 목록을 통해 상세 재진입 후 비로그인 후기 조회 확인.
- 브라우저용 회원·판매자 프로필·상품·주문은 실제 API로 준비했으며 구매 확정 상태는 테스트 SQL fixture다. 수락·결제·납품·확정 전체를 이번 브라우저 실행에서 다시 수행한 것으로 확대하지 않는다. 개인 DB·개인 접속 파일·기존 stash는 변경하지 않았다.
